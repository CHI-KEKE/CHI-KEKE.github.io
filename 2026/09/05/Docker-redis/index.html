redis

Created2026-09-05|Updated2026-09-05|Docker
|Post Views:

docker run
│
├─ -d
│ └─ 背景執行
│
├─ –name redis-open
│ └─ Container 名稱叫 redis-open
│
├─ -p 6379:6379
│ └─ Host 6379 → Container 6379
│
├─ redis:7
│ └─ 使用 Redis 7 image
│
└─ redis-server –bind 0.0.0.0 –protected-mode no
└─ Container 啟動後執行的程式

其中 –bind 0.0.0.0 很重要。它要求 Redis Server 接受 Container 所有網路介面的連線，而不只限於 loopback。

接下來：

docker exec -it redis-open redis-cli PING

意思是：

進到正在運作的 redis-open Container 裡，執行 redis-cli PING。

所以網路路徑非常短：

┌──── redis-open container ─────┐

redis-cli
│
│ localhost:6379
▼
redis-server

└───────────────────────────────┘

正常會得到：

PONG

這個測試主要證明：

Redis Server 本身有正常啟動。

但它還沒證明 Host 的 6379 port mapping 可以正常使用。

真正比較有意思的是第三個：

docker run –rm redis:7 redis-cli -h host.docker.internal -p 6379 PING

這次你另外建立一個新的 Container。

它只是借用 redis:7 image 裡面的 redis-cli：

Container A
臨時 redis:7 container
│
│ redis-cli
│
│ -h host.docker.internal
│ -p 6379
▼
Host
│
│ Host port 6379
│
│ Docker port forwarding
▼
Container B
redis-open
│
▼
redis-server :6379

所以你原本畫的圖：

[ redis-cli container ]
|
| 連線 host.docker.internal:6379
v
[ Host (你的電腦) ]
|
| docker -p 6379:6379
v
[ redis-open container ]
|
v
[ redis-server ]

是對的。

host.docker.internal 又是什麼？

假設你在 Container 裡寫：

redis-cli -h localhost -p 6379

這裡的 localhost 指的是：

目前這個 redis-cli Container 自己

它找不到另一個 redis-open 裡的 Redis。

所以 Docker Desktop 提供：

host.docker.internal

讓 Container 可以找到 Host 電腦。

於是：

redis-cli -h host.docker.internal -p 6379 PING

可以理解成：

「從這個 Container 出發，去找我的 Host 電腦的 6379。」

而 Host 之所以有 6379 可以連，是因為前面做了：

-p 6379:6379

也就是：

Host:6379
│
▼
redis-open:6379

最後 Redis 收到：

PING

回：

PONG

因此這兩個 PING 驗證的東西有明顯差別：

測試 路徑 可以證明
docker exec … redis-cli PING Redis Container → Redis Redis 本身正常
另一個 Container → host.docker.internal:6379 Container → Host → Port Mapping → Redis Container Redis 可以經由 Host 的 6379 被連到

你可以把第二個想成：我特地站到 Redis Container 外面，再繞 Host 的入口進去。

這也是為什麼這個實驗對理解 -p 6379:6379 特別有用。

error during connect: Get “http://%2F%2F.%2Fpipe%2FdockerDesktopLinuxEngine/v1.46/containers/json”: open //./pipe/dockerDesktopLinuxEngine: The system cannot find the file specified.

Docker CLI 有安裝，但 Docker Desktop 的 Linux Engine 沒有啟動。

你現在這個錯誤：

open //./pipe/dockerDesktopLinuxEngine:
The system cannot find the file specified.

表示 docker 指令正在找 Docker Desktop 的 Linux Engine，但那個 named pipe 目前不存在。

請先做這一步：

打開 Windows 的 Docker Desktop
等到 Docker Desktop 顯示 Engine 已經啟動，例如介面顯示 Engine running
